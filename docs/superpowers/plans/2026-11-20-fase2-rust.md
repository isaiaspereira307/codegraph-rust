**Architecture:** O `Collector` de `crates/codegraph-parser/src/languages/rust.rs` deixa de

busca léxica, para alvos com caminho que o CRG guarda como texto.

## Forma do CRG para Rust (medida no corpus `rust` e em sonda direta)

- Nós: `struct_item`/`enum_item`/`trait_item` → `Class`; `function_item` e
  `function_signature_item` → `Function`. `impl_item`, `mod_item` e `macro_invocation` não
  geram nó. Itens de `mod tests { … }` ficam sem o módulo no nome (`F::new_repo_is_empty`).
- `impl [Trait for] T { … }`: escopo de classe `T` (último segmento do caminho, sem genéricos)
  para os métodos, em qualquer profundidade (inclusive dentro de `fn`); métodos de trait
  (assinaturas e default) ficam em `F::Trait.m`.
- `IMPLEMENTS F::T → alvo`, linha do `impl`: alvo = `F::Trait` se o traço (um segmento) é
  nome definido no topo do arquivo; senão o caminho `a::b::Trait` como texto (sem genéricos).
- Decorators: `attribute_item` irmãos anteriores do `function_item`, de trás para frente, sem
  `#[`/`#![` e `]` (`test`, `tokio::test`); para no primeiro irmão que não é `attribute_item`.
  `_TEST_ANNOTATIONS` já está em `test_detection.rs`.
- `defined_names` = nomes de `struct`/`enum`/`trait`/`fn` filhos diretos da raiz do arquivo.
  Módulo inline `mod m { fn f… }` (com corpo, filho da raiz) registra `m::f` para struct/enum/
  trait/fn filhos diretos do corpo.
- Chamador: `fn` que envolve a chamada; dentro de `impl`/`trait` fora de `fn` (const
  associada) ou fora de tudo → `File`.
- Nome da chamada (`call_expression`): caminho do `function` por `_rust_path_segments`
  (`identifier`, `type_identifier`, `crate`, `self`, `super`; `scoped_identifier`/
  `scoped_type_identifier` = path + name; `generic_type`/`generic_function` desembrulham,
  descartando argumentos) juntado por `::` → `HashMap::new`, `Vec::<u8>::new` → `Vec::new`,
  `g::<u8>()` → `g`. Se vazio e o `function` (desembrulhando `generic_function`) é
  `field_expression` → nome = `field`, `receiver` = texto do `value` (`self.users`, `repo`).
  Outras formas (`(f)()`, `h()()`) não geram chamada.
- `macro_invocation` é chamada: nome = texto do campo `macro` (`println`,
  `tokio::select`, `log::info`), sem `!`.
- Alvo:
  - `receiver == "self"` dentro de escopo de classe `C` → `F::C.m`.
  - Nome `Self::m` em escopo `C` → `F::C.m`.
  - Outro receptor → nome solto, com `receiver` na aresta.
  - Nome com `::` (≥ 2 segmentos, prefixo ≠ `["Self"]`): prefixo de um segmento em
    `defined_names` → `F::X.m`; prefixo de um segmento `m` com `m::nome` de módulo inline →
    `F::nome`; senão o texto do caminho, marcado `crg_verbatim_target` (o CRG ainda tenta
    módulos entre arquivos — fora do escopo).
  - Nome simples (inclui macros simples) → texto; o catálogo resolve como hoje.
- Guarda morta: chamada (inclusive macro) dentro do `consequence` de um `if_expression` cuja
  condição (desembrulhando parênteses) é `boolean_literal` `false` → descartada. A subida para
  em `impl_item` (método em `impl` dentro de `if false` continua vivo). `else` e `if true`
  vivos; `false && false` vivo.
- `use`: um `IMPORTS_FROM File → caminho` por item achatado (`_parse_rust_use_node`):
  `use a::b::C` → `a::b::C`; `use a::{b, c::D}` → `a::b`, `a::c::D`; `use a::{self}` → `a`;
  `use a::B as X` → `a::B`; `use a::{b::{c, d}}` → `a::b::c`, `a::b::d`. Glob: `use_wildcard`
  não tem campo `path`, então `use super::*`/`use std::io::*` no topo não geram nada; dentro de
  lista com prefixo (`use a::{b::*}`) gera o prefixo (`a`).
- `TESTED_BY` sai sozinho do `finalize` quando os `Test` e seus CALLS existem (inclusive para
  alvos de texto, `assert → teste`).

## Review Focus

1. `impl` de tipo genérico/caminho (`impl<T> Foo<T>`, `impl fmt::Display for a::Foo`): métodos
   em `F::Foo.m`, IMPLEMENTS alvo `fmt::Display` texto — teste na Task 1.
2. Chamada depois de um `impl` aninhado em `fn` (`fn main(){ impl S { fn run(){} } S::run(); }`)
   sai de `main`, não de `S.run` — teste na Task 2.
3. `#[test]` separado da `fn` por comentário não marca teste (o CRG para no primeiro irmão que

4. `HashMap::new` em arquivo com `impl Foo { fn new() }` não vira `Foo.new` (verbatim) — teste
   na Task 2 (extrator) e na Task 4 (harness).
5. `use` com `as`, `self` e grupos aninhados; glob no topo não gera aresta — teste na Task 3.
