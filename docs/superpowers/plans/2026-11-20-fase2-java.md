> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** levar o corpus `java` do harness de paridade a Jaccard 1.0 em nós, CALLS, INHERITS e
INJECTS, mantendo CONTAINS e IMPORTS_FROM em 1.0.

**Architecture:** O `JavaCollector` (`crates/codegraph-parser/src/languages/java.rs`) deixa de
gravar nós `package`, troca o `current_function_id` que nunca é limpo por uma pilha de funções,
grava `new X()` e `X::m` como chamadas, guarda o receptor (`receiver`) e resolve no próprio
arquivo o que o CRG resolve em `_collect_typed_call_targets` (receptor tipado ou de classe cujo
tipo é declarado no arquivo) e em `_resolve_call_targets` (nome solto sem receptor → primeiro
símbolo homônimo do arquivo). Gera `INHERITS` (texto) e `INJECTS` (texto) com `java_type`. Um
pré-passe novo no indexer (`crates/codegraph-mcp/src/spring.rs`), sobre os nós e arestas do
projeto inteiro antes do catálogo, porta `spring_resolver.py`: chamada cujo receptor é um campo
injetado vai para a implementação única do tipo injetado (ou para o próprio tipo).

## Forma do CRG para Java (medida no corpus `java`)

- Sem nó para `package`; o pacote vai para o atributo `java_package` das classes.
- `class`/`interface`/`enum` → `Class` (enum hoje vira `Type`). Atributo `java_kind`:
  `interface`, `abstract` (modificador `abstract`) ou `concrete`.
- Chamadas: `method_invocation` → nome do método; `object_creation_expression` → primeiro
  `type_identifier`/`scoped_type_identifier` em profundidade (`new HashMap<>()` → `HashMap`);
  `method_reference` → último filho nomeado se `identifier`/`type_identifier`, receptor = texto
  do primeiro.
- Chamador: método/construtor que envolve a chamada; fora deles (inicializador de campo) →
  `File`.
- Receptor de `method_invocation` (`_get_java_method_and_receiver`): `a.m()` → `a`;
  `this.f.m()` → `f` (marcado como campo); `this.m()` → `this`; `super.m()`, `x.y().m()`,
  `"s".m()` → sem receptor. Chamada sem objeto (`m()`) → sem receptor.
- Tipos ligados (escopo léxico; inicializador visto antes da declaração):
  classe → campos (`field_declaration`, sem entrar em classes/métodos aninhados);
  método/construtor → campos da classe + `formal_parameter`/`spread_parameter`;
  `block` → copia; `local_variable_declaration` → acrescenta. `var x = new T()` → `T`.
  Tipo = `_base_type_name`: último segmento do primeiro nome; `Optional`/`Annotated`/`Type`
  desembrulham o argumento genérico; `T[]`, `List`/`Map`/`Set`/`Collection`/…, primitivos e
  `void` → nada.
- `this.f.m()` usa só os campos da classe. Receptor sem tipo ligado e com inicial maiúscula,
  importado ou declarado no arquivo → o próprio receptor é o tipo (chamada estática).
- Tipo declarado no arquivo → alvo `<arquivo>::<Tipo>.<m>` (mesmo sem `m` existir).
  Senão o nome solto continua, com `receiver`.
- Sem receptor (inclui `super.m()` e `new X()`), nome igual a um `Function`/`Class`/`Test` do
  arquivo → o primeiro na ordem do arquivo (`super.save` → `UserRepository.save`).
- `INHERITS Classe → base` (texto): `superclass` e `super_interfaces/type_list`, filhos
  `type_identifier`/`generic_type` (texto inteiro, com argumentos). Interfaces não geram.
- `java_type` de um tipo: importado → nome importado (`+ .resto`); `a.B` com inicial minúscula →
  ele mesmo; senão `<pacote>.<tipo>`; com import `*` e cabeça não importada → bare.
- `INJECTS Classe → TipoDoCampo` (texto), por declarador de `field_declaration` não `static`
  cujo tipo é `type_identifier`/`generic_type`/`array_type` (nome externo):
  `@Autowired`/`@Inject`/`@Resource` → `field`; classe com `@AllArgsConstructor` →
  `constructor_lombok_all`; `@RequiredArgsConstructor` sem inicializador e (`final` ou
  `@NonNull`) → `constructor_lombok`. Construtor com anotação de injeção → um `INJECTS` por
  `formal_parameter` com `type_identifier` (`constructor`, `field_name` = nome do parâmetro).
- Spring (pós-passe, `spring_resolver.py`): CALLS Java com `receiver` cujo par
  `(classe do chamador, receiver)` é um `field_name` de INJECTS → método `m` do alvo original:
  implementações do tipo injetado (fontes de INHERITS cujo `java_type`/texto é o tipo), sem
  testes se o chamador não é teste, só quando o tipo é `interface`/`abstract` ou desconhecido;
  uma só → `<Impl>.m`; senão a classe única com esse `java_type` → `<Classe>.m`; senão
  `<tipo>.m`. Método existente ganha o `qualified_name` do nó.
- Teste: `Function` com anotação `@Test`/`@ParameterizedTest`/`@RepeatedTest`/`@TestFactory`
  (ou `org.junit…Test`) → `Test`, além das regras de nome/caminho já existentes.

CALLS esperadas (sem linha; `S` = `SampleJava.java::`, `D` = `SpringDI.java::`):

```
SampleJava.java -> HashMap
S CachedRepo.save -> S UserRepository.save
S InMemoryRepo.findById -> get, ofNullable
S InMemoryRepo.save -> S User.getId, println, put
S UserService.createUser -> S User, S UserRepository.save
S UserService.getUser -> S UserRepository.findById
D AppConfig.orderRepository -> D JpaOrderRepository
D NotificationService.notify -> D JpaOrderRepository.findById
D OrderService.placeOrder -> D JpaOrderRepository.save, D NotificationService.notify, D Order.getId
```

INHERITS: `S CachedRepo -> InMemoryRepo`, `S InMemoryRepo -> UserRepository`,
`D JpaOrderRepository -> OrderRepository`. INJECTS: `D AuditLogger -> OrderRepository`
(constructor), `D NotificationService -> OrderRepository` (field),
`D OrderService -> NotificationService`, `D OrderService -> OrderRepository`
(constructor_lombok).
